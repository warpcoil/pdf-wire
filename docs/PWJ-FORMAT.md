# PWJ draft format

**Version 2** · used by PDF Wire test builds 3 to 6

A `.pwj` file is a draft of a document made in the editor. It holds the content and settings needed to rebuild the document and export it as a tagged PDF. It is plain **UTF-8 JSON**, so it can be read, diffed and generated by other tools.

| | |
| --- | --- |
| File extension | `.pwj` (the editor also opens `.json` files with the same content) |
| Media type | `application/json` |
| Encoding | UTF-8, no byte-order mark |
| Browser autosave key | `apdf.draft.v1` in `localStorage` (same content) |

## 1. Top-level object

```json
{
  "format": "apdf-draft",
  "version": 2,
  "title": "Riverside Library Visitor Guide",
  "lang": "en-IE",
  "author": "",
  "pageSize": "A4",
  "font": "atkinson",
  "blocks": []
}
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `format` | string | Yes | Always `"apdf-draft"`. Identifies the file as a draft. |
| `version` | integer | Yes | Format version. The current version is `2`. See [section 7](#7-version-history-and-migration). |
| `title` | string | Yes | Document title. Written to XMP `dc:title` and the Info dictionary, and shown in the viewer's title bar. Export is blocked while it is empty. |
| `lang` | string | Yes | Main language as a BCP 47 tag, such as `en-IE`, `ga` or `fr`. Written to the catalog `/Lang`. It must match `^[A-Za-z]{2,3}(-[A-Za-z0-9]{1,8})*$`. |
| `author` | string | No | Written to XMP `dc:creator` and Info `/Author` when not empty. |
| `pageSize` | string | Yes | `"A4"` (595.28 × 841.89 pt) or `"Letter"` (612 × 792 pt). Any other value is treated as A4. |
| `font` | string | No | Default font family key (see [4.1](#41-font-family-keys)). Defaults to `"atkinson"`. |
| `blocks` | array | Yes | The content, in **reading order**. |
| `remediation` | object | No | Present in drafts rebuilt from an existing PDF. See [section 10](#10-remediation-fields). |

## 2. Blocks

Every block is an object with these common fields:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | string | Yes | Unique within the file. The editor generates `b` followed by 8 random characters, but any unique string is valid. |
| `type` | string | Yes | One of `heading`, `paragraph`, `list`, `image`, `table`, `pagebreak`. |
| `style` | object | No | Text style overrides (see [section 3](#3-text-style)). Used by `heading`, `paragraph` and `list`; ignored by the other types. |
| `src` | object | No | Where a rebuilt block came from in the original PDF. See [section 10](#10-remediation-fields). |

**The order of `blocks` is the reading order of the exported PDF.**

### 2.1 `heading`

```json
{ "id": "b1", "type": "heading", "level": 1, "text": "Riverside Library Visitor Guide", "style": {} }
```

| Field | Type | Description |
| --- | --- | --- |
| `level` | integer 1–6 | Becomes `H1`–`H6` in the PDF. |
| `text` | string | Plain text. Line breaks are treated as spaces. An empty heading blocks export. |

### 2.2 `paragraph`

```json
{ "id": "b2", "type": "paragraph", "text": "Everything you need to plan a visit.", "style": { "font": "literata" } }
```

| Field | Type | Description |
| --- | --- | --- |
| `text` | string | Plain text. Empty paragraphs are skipped on export. |

### 2.3 `list`

```json
{ "id": "b3", "type": "list", "marker": "decimal", "items": ["Ground floor", "First floor"], "style": {} }
```

| Field | Type | Description |
| --- | --- | --- |
| `marker` | string | Bullet or numbering style (see [4.2](#42-list-markers)). Defaults to `"disc"`. |
| `items` | string[] | One string per item. Empty items are skipped on export. A list with no non-empty items blocks export. |

### 2.4 `image`

```json
{
  "id": "b4", "type": "image",
  "name": "library-entrance.png",
  "data": "/9j/4AAQSkZJRgABAQ…",
  "w": 1600, "h": 900,
  "alt": "Front of Riverside Library: a cream building with a wide central door.",
  "decorative": false,
  "caption": "", "showCaption": false,
  "widthPct": 100, "align": "left"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `name` | string | Original file name, for display only. |
| `data` | string | Base64-encoded **baseline JPEG**, RGB, with no `data:` URL prefix. An empty string means no image has been chosen yet, which blocks export. |
| `w`, `h` | integer | Pixel width and height of `data`. They must match the JPEG. |
| `alt` | string | Alternative text, written as `/Alt` on the `Figure`. Required when `decorative` is false. |
| `decorative` | boolean | `true` saves the image as an `/Artifact`, which screen readers skip, and ignores `alt`. |
| `caption` | string | Visible caption text. |
| `showCaption` | boolean | When `true` and `caption` is not empty, the caption is written as a paragraph under the image. |
| `widthPct` | number 10–100 | Width as a percentage of the text column. Height follows the aspect ratio and is capped at 70% of the page's text area. |
| `align` | string | `"left"`, `"center"` or `"right"`. |

When the editor adds an image, it scales it to at most 2000 px on the longest side and flattens any transparency onto white before encoding it as JPEG. Other tools should do the same, because the writer embeds `data` as-is with `/DCTDecode`.

### 2.5 `table`

```json
{
  "id": "b5", "type": "table",
  "rows": [["Day", "Opens", "Closes"], ["Monday to Friday", "9:00", "18:00"]],
  "headerRow": true, "headerCol": false,
  "caption": "Library opening hours",
  "size": 10, "headerFill": "#E8EEF4", "stripes": false, "repeatHeader": true
}
```

| Field | Type | Description |
| --- | --- | --- |
| `rows` | string[][] | Cell text, row by row. Every row must have the same number of cells: 1 to 8 columns and 1 to 200 rows. |
| `headerRow` | boolean | First-row cells become `TH` with `/Scope /Column`. |
| `headerCol` | boolean | First-column cells (below any header row) become `TH` with `/Scope /Row`. At least one of `headerRow` and `headerCol` must be true to export. |
| `caption` | string | Written as a `Caption` element, the first child of the `Table`. |
| `size` | number 7–24 | Text size in points. Defaults to 10. |
| `headerFill` | string | Header shading as `#RRGGBB`, or `""` for none. Checked for contrast against the header text. |
| `stripes` | boolean | Shades alternate body rows (`#F1F3F6`). |
| `repeatHeader` | boolean | Redraws the header row at the top of each continuation page as an artifact. It is not repeated in the tag tree. |

Tables use the document's default font, with bold for header cells.

### 2.6 `pagebreak`

```json
{ "id": "b6", "type": "pagebreak" }
```

The next block starts on a new page. Page breaks have no tag and are not announced.

## 3. Text style

`style` is an object on `heading`, `paragraph` and `list` blocks. Every field is optional. A missing field, `null` or an empty object means "use the default".

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `font` | string | the document's `font` | Font family key (see [4.1](#41-font-family-keys)). |
| `size` | number 7–72 | headings: 24, 18, 15, 13, 12, 11 pt for H1–H6; other text: 11 pt | Font size in points. |
| `bold` | boolean | `true` for headings, `false` otherwise | |
| `italic` | boolean | `false` | |
| `color` | string | `"#17191E"` | Text colour as `#RRGGBB`. Export is blocked if the contrast against white is below 4.5:1, or 3:1 for text that is at least 18 pt, or at least 14 pt and bold. |
| `align` | string | `"left"` | `"left"`, `"center"` or `"right"`. Justified text is not supported. |
| `lineHeight` | number | 1.25 for headings, 1.45 otherwise | Line spacing as a multiple of the font size. The editor offers 1.15, 1.25, 1.45, 1.6 and 2.0. |

## 5. How blocks map to PDF tags

On export, the blocks become children of a single `Document` structure element, in array order.

| Block | Structure in the PDF |
| --- | --- |
| `heading` | `H1`–`H6` |
| `paragraph` | `P` |
| `list` | `L` (with `/ListNumbering`) › `LI` › `Lbl` + `LBody` |
| `image` (informative) | `Figure` with `/Alt` and a Layout `/BBox` |
| `image` (decorative) | `/Artifact`, no structure element |
| image caption | `P` after the figure |
| `table` | `Table` › optional `Caption`, then `TR` › `TH` (with `/Scope`) or `TD` |
| `pagebreak` | Nothing; layout only |

The writer also adds, on every export:

- **Pages:** page numbers ("Page n of N") as `/Artifact /Pagination /Footer`; table rules and shading as `/Artifact /Layout`; repeated table headers as `/Artifact /Pagination /Header`; `/Tabs /S` on every page.
- **Bookmarks:** generated from the headings (`/Outlines`, with `/PageMode /UseOutlines`).
- **Metadata:** XMP with `dc:title`, `dc:language`, optional `dc:creator`, and `pdfuaid:part` = 1; `/MarkInfo << /Marked true >>`; `/ViewerPreferences << /DisplayDocTitle true >>`.

Layout: margins are 64 pt left and right and 72 pt top and bottom. A heading is moved to the next page rather than left alone at the foot of a page.

## 6. Validation and loading

A file is accepted as a draft when all of these are true:

- it parses as JSON
- `format` is `"apdf-draft"`
- `title` is a string
- `blocks` is an array, and every block has a string `id` and a `type` from the list in [section 2](#2-blocks)

The editor also accepts the legacy type `shape` (see [section 7](#7-version-history-and-migration)).

After loading, the editor fills in defaults for missing fields, so minimal files are valid. For example, a list without `marker` gets `"disc"`, and a table without `size` gets 10.

Content problems don't stop a file from loading. They appear in **Checks before export** and block export until fixed. Examples: an empty title, a missing language, an image with no alternative text, or a table with no header cells.

Unknown top-level and block fields are kept in memory and written back on the next save, but they are otherwise ignored.

## 7. Version history and migration

| Version | Build | Changes |
| --- | --- | --- |
| 1 | Test build 2 | First version. No `style`; lists used `"ordered": true/false`; tables had no `size`, `headerFill`, `stripes` or `repeatHeader`; images had no `widthPct` or `align`. |
| 2 | Test builds 3–6 | Added `font`, `style`, `marker`, table look options, and image width and alignment. |

Older files are upgraded automatically when opened:

- `ordered: true` becomes `marker: "decimal"`, and `false` becomes `"disc"`.
- Missing table and image fields get their defaults.
- Font keys from earlier builds are mapped: `sans` → `inter`, `serif` → `sourceserif`, `hyper` → `atkinson`.
- Fixed positioning and layers existed only in build 3 and were then removed. Blocks of type `shape` are dropped, and `pos` and `z` fields are removed, which puts positioned items back into the text flow.

The editor does not change `version` when it upgrades a file in memory.

## 8. Example

A complete draft with one of each block type. The image data is shortened here; a real file holds the full base64 JPEG.

```json
{
  "format": "apdf-draft",
  "version": 2,
  "title": "Riverside Library Visitor Guide",
  "lang": "en-IE",
  "author": "Riverside Library",
  "pageSize": "A4",
  "font": "atkinson",
  "blocks": [
    { "id": "b1", "type": "heading", "level": 1, "text": "Riverside Library Visitor Guide", "style": {} },
    { "id": "b2", "type": "paragraph", "text": "Everything you need to plan a visit. Fáilte romhat – you are welcome.", "style": { "lineHeight": 1.6 } },
    { "id": "b3", "type": "image", "name": "entrance.png", "data": "/9j/4AAQSkZJRgABAQAAAQABAAD…", "w": 800, "h": 450,
      "alt": "Front of Riverside Library: a cream building with a wide central door.", "decorative": false,
      "caption": "The main entrance on Quay Street", "showCaption": true, "widthPct": 80, "align": "center", "style": {} },
    { "id": "b4", "type": "heading", "level": 2, "text": "Opening hours", "style": {} },
    { "id": "b5", "type": "table",
      "rows": [["Day", "Opens", "Closes"], ["Monday to Friday", "9:00", "18:00"], ["Saturday", "10:00", "16:00"]],
      "headerRow": true, "headerCol": false, "caption": "Library opening hours",
      "size": 10, "headerFill": "#E8EEF4", "stripes": false, "repeatHeader": true, "style": {} },
    { "id": "b6", "type": "pagebreak", "style": {} },
    { "id": "b7", "type": "heading", "level": 2, "text": "Services on each floor", "style": {} },
    { "id": "b8", "type": "list", "marker": "disc",
      "items": ["Ground floor: lending and returns", "First floor: study spaces", "Second floor: local history"], "style": {} }
  ]
}
```

## 9. Writing PWJ files with other tools

PWJ is a convenient target for converting content from other systems into accessible PDFs: generate the JSON, open it in the editor, review the checks, then export.

- **Use unique `id` values.** Duplicates make selection and editing unreliable.
- **Keep text plain.** There is no inline formatting, and HTML or Markdown markup is shown as literal characters.
- **Encode images as baseline RGB JPEG** in base64 with no `data:` prefix, and set `w` and `h` to the real pixel size.
- **Use one H1 and don't skip heading levels.** The editor will flag it if you do.
- **Write real alternative text,** or set `decorative: true` deliberately. Don't generate placeholders such as "image" or a file name; the checker warns about these.
- **Leave out `style` fields** you don't need. Defaults are applied when the file is loaded.

## 10. Remediation fields

A draft made with **Remediate an existing PDF › Rebuild** carries two optional extras. Both are ignored by the PDF writer, so removing them changes nothing in the exported PDF.

### 10.1 `remediation` (top level)

```json
"remediation": {
  "source": "untagged-council-report.pdf",
  "pages": 2,
  "method": "rebuild",
  "created": "2026-10-27T18:40:12.000Z",
  "finished": false,
  "items": [
    { "id": "r4k2x9qa", "kind": "table", "blockId": "b7f3k2pq", "page": 1,
      "title": "Check the table on page 2", "detail": "Found from its ruling lines: 5 rows, 4 columns. …", "done": false }
  ],
  "removed": [ { "page": 0, "text": "Page 1 of 2", "why": "page number" } ]
}
```

| Field | Type | Description |
| --- | --- | --- |
| `source` | string | File name of the original PDF. |
| `pages` | integer | Its page count. |
| `method` | string | Always `"rebuild"`; tag-in-place work isn't saved as a draft. |
| `created` | string | ISO 8601 time the draft was made. |
| `finished` | boolean | `true` once **Finish review** is chosen: the panel is hidden and unchecked items stop showing as warnings. |
| `items` | array | The review list, in display order. |
| `removed` | array | Headers, footers, page numbers and decorations that were left out, for the record: `page` (0-based), `text` (or `"Image"`) and `why`. |

Each review item:

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Unique within the list. |
| `kind` | string | `alt`, `table`, `headings`, `meta`, `list`, `links`, `fonts` or `layout`. |
| `blockId` | string | The block it is about, if any. Items whose block was deleted are hidden. |
| `page` | integer | 0-based page in the original, if any. |
| `flag` | string | For `layout` items: `columns`, `rotated`, `overlap`, `vector`, `forms`, `grid` or `scan`. |
| `title`, `detail` | string | What is shown. |
| `done` | boolean | Ticked off. For `alt` items this is worked out from the image: done when it has alternative text or is decorative. |

While `finished` is not `true`, every item that isn't done, other than `alt`, appears as a warning in **Checks before export**. Missing alternative text is already an error.

### 10.2 `src` (on any block) and `altSuggestion` (on images)

```json
"src": { "page": 1, "rect": [64, 512.3, 531.3, 638.9] }
```

`page` is 0-based. `rect` is `[x0, y0, x1, y1]` in PDF points from the bottom-left corner of that page's media box. **Compare with original** outlines it.

`altSuggestion` on an image block holds the alternative text the original PDF had, if any. It is only offered as a suggestion; `alt` stays empty until you confirm a description.
